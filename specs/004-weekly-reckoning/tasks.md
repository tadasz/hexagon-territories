# Tasks: Weekly Reckoning

**Input**: Design documents from `/specs/004-weekly-reckoning/` (`plan.md`, `research.md`, `data-model.md`, `contracts/openapi.yaml`, `quickstart.md`)

**Prerequisites**: `plan.md` (required), `spec.md` (user stories), `data-model.md`, `contracts/`, `research.md`

**Tests**: Requested by the spec (Constitution V; FR-019, SC-001–SC-008 name tests explicitly), so test tasks are part of every stream and are listed inside the task that produces the code they cover.

**Organization**: Tasks are grouped into **two work streams**. Stream A (api) does all product work on disjoint paths from Stream B; Stream B (integration) runs after A is merged and owns root files, docs, CI, analysis and convergence. There is **no iOS stream** (the map is feature 005). Each task maps to one pull request and carries a one-line acceptance check (`→ Check:`). Semantics are fixed in `plan.md` "Shared Semantics" and `research.md` — implement them from there. Feature 003 is being implemented at the same time: the "Dependencies on 003" table in `plan.md` says what each task waits for or codes against; Stream A **merges after 003's Stream A** because both edit `apps/api/src/{app,errors,config}.ts`, `src/jobs/{index,run}.ts`, `src/plugins/openapi.ts`, `src/modules/me/purge.ts` and `drizzle/`.

## Format: `[ID] [P?] [Stream] [Story] Description — paths → Check: acceptance`

- **[P]**: can run in parallel with other [P] tasks in the same stream (different files, no dependency on an unfinished task)
- **[A]**/**[B]**: owning stream; **[US1]…[US5]**: user story from `spec.md` for traceability (Stream B tasks carry the stories they close)
- Root files (`package.json`, `pnpm-workspace.yaml`, `turbo.json`, `tsconfig.base.json`, `eslint.config.mjs`, `.prettierrc`, `.prettierignore`, `.gitignore`, `README.md`, `CLAUDE.md`, `pnpm-lock.yaml`, `.github/workflows/*`, `docs/**`) are **owned by nobody in A**; only Stream B edits them. A may install `h3-js` package-locally but never hands over `node_modules`, `dist` or a lockfile.
- Never edit `packages/territory-rules/**`, `packages/h3-fixtures/**`, `apps/ios/**` or `docs/territory-rules.md` in this feature: no rule changes, no iOS work (Constitution II; FR-020).
- Never write `hex_week_contribution` or call anything but 003's `finishWalk`/autofinish for walks (Constitution I/II).
